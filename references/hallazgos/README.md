# Hallazgos del proyecto

Aquí registramos lo que encontramos al explorar, preparar y modelar
los datos, para darle seguimiento en equipo.

## Registrar un hallazgo

1. Revisa si alguien ya registró el mismo problema.
2. Copia `plantilla.yaml` en la carpeta de la etapa donde lo detectaste.
3. Nombra el archivo `H-iniciales-numero-descripcion.yaml`.
   Ejemplo: `H-co-001-fechas-invalidas.yaml`.
4. Completa el título, hallazgo y evidencia.

Cada integrante lleva su propio consecutivo.
El archivo conserva su nombre y ubicación durante todo el seguimiento.

## Dar seguimiento

- `pendiente`: todavía falta atenderlo.
- `en_revision`: alguien está investigándolo o trabajando en la solución.
- `resuelto`: la decisión y su resultado ya están documentados.

Quien lo atiende se anota como responsable y actualiza la acción,
la resolución y el estado. Coordinen las ediciones del mismo hallazgo
y compartan los cambios mediante Pull Request.

## Documentar la resolución

Explica qué se hizo y cómo se comprobó el resultado.
Si hubo cambios de código, indica la función o el Pull Request.

Las correcciones reutilizables van en el código del proyecto.
Este archivo documenta su seguimiento.

Resolver también puede significar conservar los datos sin cambios,
siempre que se explique por qué.
